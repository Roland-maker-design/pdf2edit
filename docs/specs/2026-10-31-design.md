# pdf2edit — 设计文档

- 日期：2026-10-31
- 状态：草稿，待确认
- 一句话：**把来源正规的电子版 PDF，转成可编辑的活内容；本地、离线、免费开源。**

---

## 1. 意图

用户手里有一份正常的 PDF（Word 导出、LaTeX 编译、排版软件生成、浏览器打印），想要的是**能接着改的东西**——能改字的 Word、能算的 Excel、能讲的 PPT、能喂给 AI 的 Markdown、能贴进网站的 HTML。

不是"看起来一模一样"，是"**真的能改**"。

之所以有这项目：市面上的免费工具转完不能直接用，用户还得逐段校对。我们的招牌是**转完不用审**。

## 2. 目标

- 电子版 PDF → 五种可编辑格式：docx、xlsx、pptx、md、html
- 全程本地，不联网、不上传、不收集任何文件
- 结构正确：标题是标题、表格是表格、段落是段落、阅读顺序对
- 零配置：GUI 拖进去，或一行命令
- 转出来能被目标软件正常编辑（Word 里改样式全篇生效、Excel 里真能求和）

## 3. 非目标

- 扫描件、手机拍的照片、伪电子版（扫描图 + 烂 OCR 文本层）
- 图片输出——截图能干的事，不需要我们
- 保版式（绝对定位文本框）——点进去还是碎的，等于把截图装进 Word
- 公式转 LaTeX——明确不支持，保留为图片
- 云端处理、账号体系、计费

## 4. 反目标（即使技术跑通也算失败）

- 什么都能转，但每样都差一点，用户每次都得挑
- 转出来用户还得逐段校对——那招牌就没了
- 程序在用户机器上散落一堆临时文件

## 5. 已经定下的（你的决定）

1. 只处理**电子版 PDF**；来源不正的、隐私内容（合同等）不做
2. **输出让用户自己选**，不做格式猜测
3. **"全都要"作为兜底**：一键出全部格式，成本很低
4. **可编辑才算转好**；版式还原不做
5. 开源发 GitHub，不商用
6. 项目管理化，文件不散落

## 6. 我替你拍的（可以推翻）

1. **语言：先用 Python。** 理由：样本暴露的问题需要 fontTools 级别的字体/编码分析，Python 在这块的迭代速度远超其他语言。先把算法跑通、把评测台建起来，再决定要不要把核心用 Rust 重写换分发体验。
2. **IR 双性质**：语义树 + 坐标并存。语义给 md/html/docx流式 用，坐标只给结构重建用，不传输出层。
3. **先做 Markdown**：它没有版式可藏，结构错了立刻露馅，是结构层的试金石。
4. **许可证：AGPL-3.0**。因为要用 PyMuPDF（AGPL）和 pandoc（GPL），这份代码只能跟着开源。对开源项目无所谓，代价是别人不能闭源拿走。

## 7. 架构

```
分流 → 解析 → 编码修复 → 结构重建 → IR → [md | html | docx | pptx | xlsx]
```

- **分流**：判断这份 PDF 能不能转。文本覆盖率达标、有真实文本操作符、非整页图 + 薄文本层。不达标直接拒绝并说明原因，不硬转。
- **解析**：PyMuPDF 拿 glyph 级元素（坐标、字号、字体、渲染矩阵、路径、图像）。
- **编码修复**：见第 8 节，这是本项目真正的技术门槛。
- **结构重建**：行聚类（按 baseline）→ 段落 → 栏分割（XY-cut + 跨栏检测）→ 阅读顺序 → 标题层级 → 列表 → 表格 → 剔除页眉页脚。
- **IR**：文档树，节点带语义类型 + 坐标 + 置信度。
- **writers**：各自消费 IR，互不依赖。

## 8. 已发现的硬问题（来自实测样本）

对三份真实样本做了探测（`tools/probe_pdf.py`）：

| 文件 | 页数 | 每页字符 | 字体 |
|---|---|---|---|
| 01.生存游戏.pdf | 43 | 358 | LiberationSerif 子集 + SimSun-GBK-EUC-H |
| 02.侠盗罗宾汉.pdf | 71 | 162（55 页无文本层） | 同上 |
| 03.白色巨石.pdf | 34 | 550 | 同上 |

**问题一：拉丁字符整体偏移 29。**
`&RS\ULJKW` +29 → `Copyright`。恒定偏移，可以确定性校正。

**问题二：中文是错字，不是偏移。**
`本出版` 被抽成 `ᵜҖ⡸`。原因是 `SimSun-GBK-EUC-H` 走 GBK 的 CID 映射，ToUnicode 不可用，PyMuPDF 只能退化成错误的码位解释。

**根因（已确证）**：字体字典里 `ToUnicode = null`、`Encoding = /Identity-H`、`CIDToGIDMap = null`，三项全空；元数据显示 `Creator=PScript5.dll`、`Producer=Acrobat Distiller 19.0`。这是"用打印驱动生成 PDF"的典型副产物——不是加密，而是文字层从来没有过码表。

### 8.1 实测结论（spike 已验证）

| 通道 | 方法 | 结果 |
|---|---|---|
| 拉丁 / 数字 | gid + 29 = 字符 | ✅ 11,803 字符全部还原，输出可读英文 |
| 中文 | 嵌入子集轮廓 vs 系统 simsun.ttc 精确哈希 | ⚠️ 仅命中 32%（897 / 2,806） |

中文命中率低的原因是**字体版本差异**：这份 PDF 生成于 2019 年，系统 SimSun 版本更晚，部分字形被重绘，轮廓不再逐点一致。

### 8.2 方案

1. **拉丁/数字**：偏移自动检测。在 0..64 范围内试偏移，用英文词频/可打印率打分选最优。
2. **中文**：模糊轮廓匹配。归一化轮廓 → 廉价描述子粗筛（轮廓数、点数、包围盒、步进宽度）→ 距离排序；要求 Top-1 与 Top-2 有显著差距，否则该字符标记为不可信。
3. **兜底判定**：不可信字符比例超过阈值（初定 5%），整份文档判为"文字层不可靠"，拒绝转换并说明原因——不硬转。

原则：宁可拒绝，不要输出需要人肉校对的东西。


**问题三：02 号样本有 55 页没有文本层。** 属于"混合型"或图片型，需要按页分流：有文本的页正常转，无文本的页跳过并报告，不硬转。

## 9. 里程碑

- **P0**：Markdown + 编码修复 + 评测雏形（能对三份样本产出可读的 md）
- **P1**：docx 流式（真段落、真样式、真表格）
- **P2**：html 语义版 + pptx 文本框化
- **P3**：xlsx（表格识别是前置）

每阶段门槛：**评测集上不掉分**，不是"功能加了"。
