# pdf2edit — 设计文档

- 日期：2026-10-31
- 状态：草稿，待确认
- 一句话：**把来源正规的电子版 PDF，转成可编辑的活内容；本地、离线、免费开源。**

---

## 1. 意图

用户手里有一份正常的 PDF（Word 导出、LaTeX 编译、排版软件生成、浏览器打印），想要的是**能接着改的东西**——能改字的 Word、能算的 Excel、能讲的 PPT、能喂给 AI 的 Markdown、能贴进网站的 HTML。

不是"看起来一模一样"，是"**真的能改**"。

之所以有这项目：市面上的免费工具转完不能直接用，用户还得逐段校对。我们的招牌是**转完不用审**。

## 2. 目标

- 电子版 PDF → 五种可编辑格式：docx、xlsx、pptx、md、html
- 全程本地，不联网、不上传、不收集任何文件
- 结构正确：标题是标题、表格是表格、段落是段落、阅读顺序对
- 零配置：GUI 拖进去，或一行命令
- 转出来能被目标软件正常编辑（Word 里改样式全篇生效、Excel 里真能求和）

## 3. 非目标

- 扫描件、手机拍的照片、伪电子版（扫描图 + 烂 OCR 文本层）
- 图片输出——截图能干的事，不需要我们
- 保版式（绝对定位文本框）——点进去还是碎的，等于把截图装进 Word
- 公式转 LaTeX——明确不支持，保留为图片
- 云端处理、账号体系、计费

## 4. 反目标（即使技术跑通也算失败）

- 什么都能转，但每样都差一点，用户每次都得挑
- 转出来用户还得逐段校对——那招牌就没了
- 程序在用户机器上散落一堆临时文件

## 5. 已经定下的（你的决定）

1. 只处理**电子版 PDF**；来源不正的、隐私内容（合同等）不做
2. **输出让用户自己选**，不做格式猜测
3. **"全都要"作为兜底**：一键出全部格式，成本很低
4. **可编辑才算转好**；版式还原不做
5. 开源发 GitHub，不商用
6. 项目管理化，文件不散落

## 6. 我替你拍的（可以推翻）

1. **语言：先用 Python。** 理由：样本暴露的问题需要 fontTools 级别的字体/编码分析，Python 在这块的迭代速度远超其他语言。先把算法跑通、把评测台建起来，再决定要不要把核心用 Rust 重写换分发体验。
2. **IR 双性质**：语义树 + 坐标并存。语义给 md/html/docx流式 用，坐标只给结构重建用，不传输出层。
3. **先做 Markdown**：它没有版式可藏，结构错了立刻露馅，是结构层的试金石。
4. **许可证：AGPL-3.0**。因为要用 PyMuPDF（AGPL）和 pandoc（GPL），这份代码只能跟着开源。对开源项目无所谓，代价是别人不能闭源拿走。

## 7. 架构

```
分流 → 解析 → 编码修复 → 结构重建 → IR → [md | html | docx | pptx | xlsx]
```

- **分流**：判断这份 PDF 能不能转。文本覆盖率达标、有真实文本操作符、非整页图 + 薄文本层。不达标直接拒绝并说明原因，不硬转。
- **解析**：PyMuPDF 拿 glyph 级元素（坐标、字号、字体、渲染矩阵、路径、图像）。
- **编码修复**：见第 8 节，这是本项目真正的技术门槛。
- **结构重建**：行聚类（按 baseline）→ 段落 → 栏分割（XY-cut + 跨栏检测）→ 阅读顺序 → 标题层级 → 列表 → 表格 → 剔除页眉页脚。
- **IR**：文档树，节点带语义类型 + 坐标 + 置信度。
- **writers**：各自消费 IR，互不依赖。

## 8. 已发现的硬问题（来自实测样本）

对三份真实样本做了探测（`tools/probe_pdf.py`）：

| 文件 | 页数 | 每页字符 | 字体 |
|---|---|---|---|
| 01.生存游戏.pdf | 43 | 358 | LiberationSerif 子集 + SimSun-GBK-EUC-H |
| 02.侠盗罗宾汉.pdf | 71 | 162（55 页无文本层） | 同上 |
| 03.白色巨石.pdf | 34 | 550 | 同上 |

**问题一：拉丁字符整体偏移 29。**
`&RS\ULJKW` +29 → `Copyright`。恒定偏移，可以确定性校正。

**问题二：中文是错字，不是偏移。**
`本出版` 被抽成 `ᵜҖ⡸`。原因是 `SimSun-GBK-EUC-H` 走 GBK 的 CID 映射，ToUnicode 不可用，PyMuPDF 只能退化成错误的码位解释。

**根因（已确证）**：字体字典里 `ToUnicode = null`、`Encoding = /Identity-H`、`CIDToGIDMap = null`，三项全空；元数据显示 `Creator=PScript5.dll`、`Producer=Acrobat Distiller 19.0`。这是"用打印驱动生成 PDF"的典型副产物——不是加密，而是文字层从来没有过码表。

### 8.1 实测结论（spike 已验证）

| 通道 | 方法 | 结果 |
|---|---|---|
| 拉丁 / 数字 | gid + 29 = 字符 | ✅ 11,803 字符全部还原，输出可读英文 |
| 中文 | 嵌入子集轮廓 vs 系统 simsun.ttc 精确哈希 | ⚠️ 仅命中 32%（897 / 2,806） |

中文命中率低的原因是**字体版本差异**：这份 PDF 生成于 2019 年，系统 SimSun 版本更晚，部分字形被重绘，轮廓不再逐点一致。

### 8.2 方案

1. **拉丁/数字**：偏移自动检测。在 0..64 范围内试偏移，用英文词频/可打印率打分选最优。
2. **中文**：模糊轮廓匹配。归一化轮廓 → 廉价描述子粗筛（轮廓数、点数、包围盒、步进宽度）→ 距离排序；要求 Top-1 与 Top-2 有显著差距，否则该字符标记为不可信。
3. **兜底判定**：不可信字符比例超过阈值（初定 5%），整份文档判为"文字层不可靠"，拒绝转换并说明原因——不硬转。

原则：宁可拒绝，不要输出需要人肉校对的东西。



**问题三：02 号样本有 55 页没有文本层。** 属于"混合型"或图片型，需要按页分流：有文本的页正常转，无文本的页跳过并报告，不硬转。

### 8.3 真实样本验证（Word 导出 / 浏览器打印）

用真实来源跑出三个只在真文件上才暴露的问题：

| 现象 | 实测数据 | 规则修正 |
|---|---|---|
| 标题层级全错 | Word 的 H1=14pt、H2=13pt、正文=11pt，只差 1pt | 改为按字号**分档排序**，不再比绝对倍数 |
| 列表变成两列表格 | 项目符号 `•` 是独立一段（x0=90），正文在 x0=108，同一 y | 先识别"纯符号段"，同行合并成 list_item |
| 表格散成段落 | Word 单元格基线相差 2.5pt（320.3 vs 317.8） | 行聚合改用 y 中心 + 3pt 容差 |
| 浏览器打印的列表丢失 | `<ul>` 的符号是 CSS 画的，文本层里没有 | 靠缩进判定（实测偏移 30pt） |
| `91.2%` 被判成编号列表 | 正则把 `91.` 当编号 | 负向前瞻 `(?![\d%])` |

这些规则写在 `src/pdf2edit/structure.py` 的模块注释里，并由 `tests/test_pipeline.py` 固定住。

### 8.4 压测（双栏 / 跨页表格）

| 现象 | 根因 | 规则 |
|---|---|---|
| 双栏正文被拼成"两列表格" | 同一 y 的左右两栏各算一格，且列位置天然对齐 | 先按纵向空白走廊切栏，再在栏内做行聚合 |
| 右栏每一行都成列表项 | 正文左边界用了**全页**众数，右栏整体算"缩进 246pt" | 左边界必须按栏计算 |
| 双栏段内/段间分不清 | 段内行距 2.6–3.4pt、段间 10.9–11.6pt，固定 1.6×字号阈值必然误判 | 阈值 = 该栏行距中位数 + 0.6×字号，自适应 |
| 长表格被拦腰切开 | 表格列间有 129pt 空白，被当成栏间走廊 | 切栏探针**排除表格行** |
| 整页表格仍被切 | 排除后探针为空，`[] or lines` 退回全页——空集合被当成假值 | 探针为空时直接不切栏 |
| 跨页表格变两张、表头重复 | 逐页处理，且续页重复表头 | 相邻跨页表格续接，重复表头去重 |
| 表头三格丢失 | 表头居中、数据左/右对齐，列位置对不上，判定失败后只取首格 | ≥3 格直接判表；多格行不成表时也要拼起来，绝不丢格 |

### 8.5 压测二（三栏 / 页眉页脚 / 脚注）

| 现象 | 根因 | 规则 |
|---|---|---|
| 三栏被拼成 3 列表格 | 同一 y 是三段正文，而"≥3 格即表格" | 表格行必须"每格都短"（中位字符数 ≤ 12） |
| 三栏只切了一刀 | 单条走廊只能二分 | 递归 XY-cut，切完再切，最多 3 层 |
| 三栏切不开 | 栏间距仅 17pt（页宽 2.9%），门槛却是 3.5% | 门槛降到 1.5% |
| 每段末行被当表格 | 段落最后一行只有 8 字，单行"短"说明不了问题 | 必须**连续两行**短格才算表 |
| 递归切在页边空白 | 叶边区域没有文字，被判成走廊 | 只保留"两侧都有内容"的走廊，且每侧至少 3 行 |
| 单栏文档被页码切成两半 | 页码 "1" 落在右侧，凑成"右边有内容" | 页码/页脚不参与切栏 |
| 页眉页脚混进正文 | 只识别纯数字页码 | 新增：页边带（上下 7%）内且字号 < 正文 95% → 判定为页眉页脚 |

脚注：本身能单独成段，前提是段距与行距可区分——这也说明段距自适应阈值是必需的。

### 8.6 全面压测（四轮 · 28 份样本 × 5 格式）

用 `tools/stress_matrix.py` 跑矩阵，状态分四类：ok / skip（格式不适用）/ reject（闸门拒绝，预期）/ ERR（真异常）。

| 轮次 | 覆盖 | 结果 |
|---|---|---|
| A 结构特性 | 首行缩进、多级列表、代码块、上下标、中英混排 | 发现假标题与代码块丢失，已修 |
| B PDF 特性 | 旋转页、A4+A3 混排、空白页、加密、表单 | 全部正常 |
| C 规模 | 100 页、超长单行、高密度小字 | 100 页 0.07s，无压力 |
| D 异常 | 截断损坏、非 PDF、零页 | 改为友好拒绝，不再抛栈 |
| E 表格边界 | 合并单元格、单元格内换行、超大字号 | 两个表格限制，记入不支持清单 |

**修掉的两个真问题：**

- **假标题**：正文字号 10、小标题 11 时，仅大 1pt 就被判成二级标题。改为要求 `≥1.12 倍` 且 `≥1.5pt` 双重条件。
- **代码块**：等宽字体的行被并入普通段落、缩进丢失、还被误判成标题。现在识别等宽字体 → 独立的 `code` 块，md 出 ``` 围栏、html 出 `<pre>`、docx 用 Courier New 并保留换行。

**没有去攻的（明确写进 README 不支持清单）：**

- 单元格内换行会让表格散架——根子是按文字基线聚类，彻底解决要靠框线重建网格，属于独立工程
- 合并单元格（表头跨列）会被排除在表格外

**8.7 列表层级（已补）**

层级来自"列表行自身的缩进位置"聚类，而不是正文左边界——有些文档整页都是列表，根本没有正文行。两个坑：

- 表格单元格本身就是"缩进"的，会把层级顶歪 → 只从**单格行**统计缩进
- 有的列表整段都在缩进区内，基准点取众数会偏 → 改为对列表行自身的 x0 聚档

四个 writer 各按自己的方式消费层级：md 两空格缩进、html 嵌套 `<ul>`、docx 用 `List Bullet 2/3` 样式 + 缩进、pptx 用原生 `paragraph.level`。

## 9. 里程碑

- **P0**：Markdown + 编码修复 + 评测雏形（能对三份样本产出可读的 md）
- **P1**：docx 流式（真段落、真样式、真表格）
- **P2**：html 语义版 + pptx 文本框化
- **P3**：xlsx（表格识别是前置）

每阶段门槛：**评测集上不掉分**，不是"功能加了"。
